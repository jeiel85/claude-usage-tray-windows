>
> **#39 추가 사용량**: API 응답 확인 결과 `used_credits: 699, monthly_limit: null, utilization: null`. 한도 미설정 시 프로그레스 바/퍼센트를 숨기고 "X 크레딧 사용됨 (한도 미설정)" 텍스트만 표시하도록 수정. `ExtraHasLimit` 프로퍼티 추가.
>
> **계정 전환 버그**: 두 가지 원인 수정.
> 1. `CredentialService` — `Renamed` 이벤트 누락. Claude 앱(Electron)은 임시 파일에 쓴 뒤 rename하는 atomic write 방식을 사용하므로 `Changed/Created` 이벤트가 발생하지 않음. `Renamed` 이벤트 핸들러 추가.
> 2. `MainViewModel.RefreshAsync` — 이전 계정에서 발생한 `Retry-After` 대기가 새 계정 API 호출을 막는 버그. 계정 전환 시 `_apiRetryAfter` 초기화.
> 3. 폴백 추가 — FileSystemWatcher가 이벤트를 놓쳐도 2분 정기 새로고침 시 `orgUuid` 비교로 계정 전환 자동 감지.
>
> **계정 이름 기능 제거**: 실용성 낮아 Settings UI, `RenameCurrentAccount`, `AccountNames`, 관련 로컬라이제이션 전부 삭제.

### 🔍 미해결 — 5h/7d 표시값이 Claude 공식 UI와 다름 (2026-04-02 현재 조사 중)

**증상**: 앱의 5시간(0%), 7일(100%) 수치가 claude.ai 설정 → 사용량 화면(5h 75%, 7d 96%)과 다름.

**확인된 사실**:
- 계정 전환 자체는 정상 작동 (추가 사용량이 계정 1: 699크레딧 → 계정 2: 0크레딧으로 변경됨)
- API 응답 `five_hour.resets_at: null`, `utilization: 0.0` — 버킷이 리셋되었거나 아직 집계 전 상태로 추정
- Claude 공식 UI의 "현재 세션(롤링 윈도우)"과 API의 `five_hour`(고정 5시간 버킷)이 서로 다른 데이터를 보여줄 가능성 있음

**다음 확인 필요**:
- 계정 1로 다시 전환 시 앱 5h 값이 바뀌는지 → 바뀌면 계정 전환 코드는 정상, API 설계 차이가 원인
- API 엔드포인트(`/api/oauth/usage`)의 `five_hour` 필드가 Claude UI의 "현재 세션"과 동일한 윈도우인지 추가 검증 필요

## 배포 / CI 재발 방지 메모

### ❌ GitHub Actions YAML에서 bash 문법 사용 금지

**증상 (v1.15.12~v1.15.17):** GitHub Release 제목이 `v${GITHUB_REF_NAME#v}` 문자열 그대로 표시됨.

**원인:** `softprops/action-gh-release`의 `name:` 필드는 YAML 값이므로 bash 변수 치환(`${}`)이 동작하지 않음.

**올바른 방법:**
```yaml
# ❌ 잘못된 방법 — bash syntax, YAML에서 무시됨
name: "v${GITHUB_REF_NAME#v}"

# ✅ 올바른 방법 — GitHub Actions 표현식 사용
name: ${{ github.ref_name }}
```

**릴리즈 제목 깨졌을 때 수동 수정:**
```bash
gh release edit v1.X.X --title "v1.X.X"
```

### ❌ fd(framework-dependent) 빌드 폐기 결정 (v1.15.12~v1.15.17)

**목표:** .NET 런타임 미포함 슬림 빌드 제공 (로컬 ~1.4 MB 확인)

**시도한 방법들과 결과:**

| 버전 | 시도 | CI 결과 |
|------|------|---------|
| v1.15.12 | sc + fd 단일 job 순차 빌드 | fd 178 MB (sc 캐시 오염 추정) |
| v1.15.13 | WinRT 토스트 제거 → BalloonTip 전환, TFM `net9.0-windows` 변경 | fd 178 MB |
| v1.15.14 | `dotnet clean` 추가 후 재빌드 | fd 178 MB |
| v1.15.15 | TFM `net9.0-windows10.0.17763.0` 복귀 | fd ~25 MB (성공했으나 목표치 미달) |
| v1.15.16 | sc/fd를 별도 job으로 완전 분리 | fd 178 MB (다시 재발) |
| v1.15.17 | **fd 빌드 완전 제거** | sc 단독 배포로 단순화 |

**근본 원인:** CI 환경(`windows-latest` runner)에서 `--self-contained false`임에도 `Microsoft.Windows.SDK.NET.dll` (23 MB) 및 WPF 런타임 DLL이 번들링됨. 로컬 재현 불가. TFM·clean·job 분리 모두 근본 해결 실패.

**결론:**
- fd 빌드는 더 이상 제공하지 않음
- `ClaudeUsageTray-sc.exe` → `ClaudeUsageTray.exe` 파일명 단순화
- SHA256 파일도 동일하게 `ClaudeUsageTray.sha256`
